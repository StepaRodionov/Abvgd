# Scooter Auth Tester

Android-приложение для самоката Kugoo Kirin (у тебя: модель `kgkrn14`,
`GETDEVID` = `imoogoo-kgkrn14`, прошивка `BNSH10S10`). Подключается по BLE,
проходит рукопожатие (алгоритм из `KugooCrypto.kt`, порт присланного
Python-кода) и после авторизации управляет самокатом.

## Что умеет (вкладка «Управление»)

- **Свет** вкл/выкл (`HLGT=1` / `HLGT=0`; галка «Бинарный протокол света»
  включает кадры `AA070601AABB` / `AA070600ABBB`, если текстовая команда не сработала).
- **Стробоскоп** — быстрое мигание фарой. Отдельной команды стробоскопа в
  протоколе нет, поэтому приложение само быстро включает/выключает фару.
  Ползунок задаёт интервал (80–800 мс). Нижний предел упирается в скорость
  BLE-записи: если самокат не успевает, часть тактов пропускается. После
  остановки фара возвращается в прежнее состояние.
- **Гудок (эксперимент)** — в протоколе оригинального приложения команды гудка
  НЕТ. Поэтому есть подбор: кнопка «Подобрать команду» по очереди шлёт
  `+HORN=1`, `HORN=1`, `+BELL=1`, `+BEEP=1`, `+BUZZ=1`, `+SIREN=1`, `+ALRM=1`,
  `+FIND=1` (каждый раз сразу следом «=0») и пишет в лог, что ответил самокат.
  Услышал сигнал — жми «Это он!»: команда запомнится, и кнопка «ГУДОК»
  (нажал — «включить», отпустил — «выключить») будет её использовать. Если
  ничего не прозвучало — значит, в этой прошивке гудка по Bluetooth нет
  (скорее всего, он работает только от физической кнопки на руле).
- **Блокировка** `+LOCK=1/0`, **круиз** `+CRZE=1/0`, **передачи** `+MODE=n`.
- **«Проверить, что из этого поддерживает самокат»** — шлёт запросы
  `+MODE=?`, `+LOCK=?`, `+CRZE=?`, `+UNIT=?`, `HLGT=?`, показывает, что
  ответило, и делает бледнее кнопки тех функций, которые не ответили.

## Что убрано

Приборная панель со скоростью, батареей и остатком хода удалена: прошивка
`BNSH10S10` отвечает `ERROR` на все запросы (`+BAT`, `+SOC`, `+SPD`, `+ODO`,
`+RANGE`, `+TEMP`, `+ERR` и т.д.), а оригинальное приложение для `kgkrn14`
при подключении запрашивает только `+UNIT=?`. Эти данные у этой модели, судя
по всему, идут только на собственный дисплей самоката. Если во время движения
в логе (вкладка «Диагностика») вдруг появятся строки `<<` без твоего `>>` перед
ними — значит, самокат пушит данные сам, и их можно будет разобрать.

## Что исправлено в этой версии

1. **Нестабильное рукопожатие (`status=13` / «зависает на +PA<...»).**
   Шаг 7 протокола — приложение генерирует случайный код из 6 байт (0–255),
   склеенных как десятичные цифры (точная копия алгоритма самоката, см.
   `BleMutualAuthentication.java`). Длина кода плавает от 6 до 18 цифр, то есть
   запись `+PA<` + код — от 10 до 22 байт. По умолчанию BLE даёт на запись не
   больше 20 байт (ATT MTU 23 минус служебные 3), поэтому примерно в половине
   случаев запись не помещалась и Android отвечал
   `GATT_INVALID_ATTRIBUTE_LENGTH` (`status=13`). Исправлено двумя способами:
   сразу после подключения приложение запрашивает MTU 185 (`requestMtu`) и
   только после ответа ищет сервисы (если самокат не ответил — через 2 секунды
   идёт дальше само), а код дополнительно обрезается до 16 цифр, чтобы
   `+PA<` + код влезал даже в 20 байт.
2. **Возможный краш при коротком коде.** `KugooCrypto.encryptToken` читает
   первые 12 символов кода; если 6 случайных чисел давали меньше 12 цифр
   (редко, но возможно), было обращение за границы массива. Теперь код
   дополняется до минимум 12 цифр (на итоговый хэш это не влияет).
3. **Подписка на уведомления и запись идут через единую GATT-очередь** (Android
   принимает только одну GATT-операцию «в полёте» — остальные тихо терялись).

## Протокол рукопожатия

1. Приложение → `+VER?`
2. Самокат → `+VER=<версия>`
3. Приложение → `+PM?`
4. Самокат → `+PM><nonce, 12 hex>`
5. Приложение считает хэш (`KugooCrypto.kt`) → `+PM<<hash, 8 hex>`
6. Самокат → `+PM=OK` или `+PM=NK` (NK — неверный mode)
7. Приложение → `+PA<<случайный код>`, сам считает ожидаемый хэш
8. Самокат → `+PA><hash, 8 hex>`
9. Хэши совпали — «ВЗАИМНАЯ АВТОРИЗАЦИЯ ПРОЙДЕНА», приложение само переключается
   на вкладку «Управление».

`mode` (1/2/3) определяется автоматически по UUID сервиса самоката
(`KNOWN_SERVICES` в `MainActivity.kt`); вручную его нужно менять, только если
сервис не распознан и пришло `+PM=NK`.

## Как пользоваться

1. Собери APK (см. ниже), установи на телефон.
2. Включи Bluetooth (на Android ниже 12 ещё и геолокацию).
3. Нажми «Сканировать», выбери самокат в списке (вкладка «Диагностика»).
4. Дождись строки «ВЗАИМНАЯ АВТОРИЗАЦИЯ ПРОЙДЕНА» — откроется «Управление».
5. Если рукопожатие не прошло — «Запустить рукопожатие заново» в «Диагностике».
6. Поле «Ручная отправка» принимает любой текст (например `GETDEVID`);
   кнопка `CODE=` отправляет пароль/PIN (`CODE=<пароль>` → `CODE_OK`/`CODE_NG`).

## Сборка APK через GitHub Actions

1. Создай репозиторий на GitHub и залей туда все файлы с сохранением структуры
   (включая `.github/workflows/build-apk.yml`).
2. Вкладка **Actions** → сборка стартует при каждом коммите в `main` (или
   вручную: **Run workflow**).
3. По окончании открой прогон → раздел **Artifacts** → скачай
   `scooter-auth-tester-debug`, внутри `app-debug.apk`.
4. Установи APK на телефон (разреши установку из неизвестных источников).

## Структура

- `app/src/main/java/com/example/scooterauth/KugooCrypto.kt` — алгоритм хэша.
- `app/src/main/java/com/example/scooterauth/KugooAuth.kt` — протокол рукопожатия.
- `app/src/main/java/com/example/scooterauth/MainActivity.kt` — BLE-логика и UI.
- `app/src/main/res/layout/activity_main.xml` — экран (две вкладки).
- `.github/workflows/build-apk.yml` — сборка debug APK.
